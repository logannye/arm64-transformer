# Frozen numerical implementation, separate study controls

This successor uses protocol `gpu-v5-library-five-engine-v3`. Every numerical
engine, including the CPU library model, comes from revision
`c2efce299984d120b185ffab70c3808150034eaf`. Controls in this directory have a
separate, explicit source role. Changing a launcher must not silently change the
qualified mathematical implementation or import another editable checkout.

The approved v3 change selects precise FF1 for CPU Torch in both replay and
training. The width-1024 common-state failure and its raw gradients remain
development evidence. CPU library replay, optimizer and common-state gates must
be requalified; the previous CPU model cannot satisfy these gates. Unchanged
arms retain their original receipts and producer-version independent audits.
Reuse requires identical installed runtime bytes, the exact approved source
delta and unchanged comparison criteria. Common-state teacher checkpoints stay
fixed, including their original CPU producer identity.

The prospective comparison retains six widths, five engines, three seeds, two
repeats, 1,024 updates per fit, 180 fits and 1,474,560 test-token predictions.
All 2,088 admission groups and 9,858 members remain present. Full-model accuracy
blocks admission for every width and engine. Diagnostic framework primitive and
wide three-step trajectory groups keep their original scope.

The formal route is implemented. Implementation support grants no eligibility:
`frozen.verify()` requires all exact-source raw prerequisites, hosted checks,
original fixtures, hardware and runtime authority before any reserved operands
or measured fits. A prospective plan or user-supplied pass flag cannot open it.
Seeds 20261104, 20261108 and 20261112 remain unopened at this revision.
This is an explicitly maintained-library experiment; standard-release
framework acceptance and performance claims do not follow from its results.

Current components:

- `authority.py` seals the exact control/math roles, authenticates the complete
  runtime before activation and checks loaded module origins afterward.
- `audit.py` gives the existing independent repeatability/common-state auditors
  the exact frozen oracle source while retaining their independent NumPy/Torch
  environment. Candidate package paths are never activated by these auditors.
- `qualify_suites.py` reaudits the complete NumPy 2 suite evidence using the
  frozen MPS archive/stock-fixture and MLX inventory/descendant validators. It
  uses the captured interpreter and authenticated paths for dependency metadata
  discovery without importing tensor packages or executing numerical models.
- `execution.py` fixes the actual maintained-library model stages and reference
  Metal shader, validates combined shader/define hashes and checks the live
  Metal host-library origin.
- `native_assets.py` authenticates the six hosted selected-policy binaries,
  reopens their transport archives and verifies unchanged build-source bytes.
  Artifact identity does not transfer an earlier numerical qualification.
- `measurement.py` preserves the existing GPU workload and timing boundaries,
  restored warmup, strict checkpoint ties, exact replay and cleanup. It has no
  formal CLI. Its formal caller must authenticate frozen admission first.
- `evidence.py` retains lossless compressed raw pairs in the existing shared
  content-addressed store. Independent decisions read the original arrays and
  keep the frozen tolerances. Oversized headers, missing members, changed bytes
  and substituted pass flags are rejected.
- `context.py` and `worker.py` run the retained native/Metal/oracle development
  groups on exposed stream 20261103. They use the exact numerical handlers with
  explicit selected factories, fresh-process training and actual CPU tie fits.
  The job schema rejects formal fields and alternate seed selection before
  runtime activation. CPU malformed-input checks accept only their declared
  rejection, so unrelated runtime failures cannot count as passes.
- `audit_development.py` re-evaluates every retained raw comparison in those
  groups and checks the complete fresh-process/tie denominator, source roles,
  runtime origins, native assets and Metal selection. It grants no formal
  admission or measurement authority.
- `common_native_metal.py` and its independent auditor apply the same 15-case
  common-state and identical-gradient matrix to the other two engines. Together
  with the 18 framework cells this covers 30 engine/width cells and 450 cases:
  CPU states 0/8/64 at B1/B3/B16 and Adam states 0/64 for 1/2/10 fixed updates.
- `fixtures.py` authenticates the 18 original input fixtures and all 126 files
  against the published compact metadata. It transfers fixture identity only.
- `audit_dispatch.py` gives primitive, optimizer, provenance and collection raw
  audits the frozen project source and independent installed numerical packages.
  `qualification_plan.py` requires the exact completed collector/cell inventories
  before scheduling all raw re-audits. A schedule or completion flag cannot
  qualify the study without executing those audits.
- `qualify.py` executes the complete scheduled raw audits serially and requires
  exact-source hosted push/PR checks. `frozen.py` authenticates that evidence,
  both source roles, hardware, runtime and original fixtures before granting
  permission to open reserved admission operands.
- `admission_worker.py`, `audit_admission.py` and `admission.py` execute and
  independently check every retained admission member, including full-model
  accuracy at every width and the complete fresh-process/tie denominator.
- `fit.py` and `campaign.py` select admitted numerical factories explicitly,
  preserve the 180-cell rotation and stop subsequent fits after a failed fit,
  power condition or exact repeat. Completed measurement is still unaudited.
- `checkpoint_replay.py`, `audit_checkpoint.py` and `audit_campaign.py` retain
  all five engines' validation/test/B1 outputs for both best and last states:
  360 checkpoints. Independent NumPy FP64 equations cover all rows; independent
  PyTorch double equations cross-check the first/last rows per split, matching
  the original reference contract. Accuracy, engine compatibility, own-engine
  replay and all 90 exact repeat pairs remain separate gates.
  Own-engine B16 replay preserves measured full-row slicing/indexed resident
  dataset transport and its strides; B1 uses the measured resident-input path.
- `report.py` binds the complete campaign audit and produces a qualified
  performance summary only when every postrun gate passes. Ratios are paired
  by original seed. Hardware, workload, storage precision, selected internal
  arithmetic and maintained-framework scope remain explicit.

Complete prerequisite verification, admission/campaign dispatch and full saved
checkpoint auditing require the exact revision's validation. A future freeze
must bind both source roles, exact runtime,
native assets, all original fixture bytes, full prerequisite evidence and the
retained admission inventory before opening seed 20261112. Preserve a 16 GiB
disk reserve, bound raw-store growth and use one numerical worker at a time.
Campaign preflight budgets both saved states and every replay without assuming
compression or deduplication; shared raw members may save space afterward.
