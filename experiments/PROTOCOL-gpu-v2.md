# GPU engineering and matched CPU/GPU study, v2

This new phase preserves the closed CPU v6 and GPU development v1 records.
The user authorized implementation of the GPU optimization roadmap on 2026-10-29,
retaining standard MPS/compiled MLX, exact training repeatability, and fresh CPU
anchors. No previous failure is waived. Formal admission remains closed until
the complete source/runtime/input/policy contract and every required check pass.

## Fixed workload and denominator

One decoder block; four heads; context 32; FFN 2W with ReLU; three LayerNorms;
ASCII128; widths 32/64/128/256/512/1024. Reuse exact CPU v6 corpus partitions,
initial FP32 parameters and schedules. Seeds 42/43/44, two repeats, B16, eight
epochs/1024 Adam steps, 524288 processed targets per fit. Train/validation/test
contain 65536/8192/8192 targets. Adam lr=.001, betas=.9/.999, eps=1e-8; LayerNorm
population variance and eps=1e-5. Lowest own-engine validation NLL selects the
checkpoint, with the first epoch winning ties. All stored numerical state is FP32.

Five engines (cpu_arm64, cpu_torch, metal, mps, mlx) produce 180 planned fits,
72 CPU and 108 GPU, with 1474560 retained test-token predictions if complete.
Every planned cell remains in the denominator. CPU code stays at the immutable
v6 measured revision; fresh CPU/PyTorch and MPS share the selected PyTorch version.
Historical releases stay unchanged. This is a reused engineering benchmark,
not fresh assessment evidence. No test outcomes guide implementation or tuning.

## Hardware mapping and candidate selection

Target the observed M4 Max/40-core GPU and 32-thread SIMD groups; rediscover and
record actual capabilities. MSL3.1 safe math/precise functions remain selected.
Use supported FP32 SIMD-group matrices, deterministic cooperative reductions,
short-context attention fusion and grouped embedding gradients. Sensitive QKV
forward/dX retain two-float accumulation; attention and normalization retain
the demonstrated compensated precision. No native GPU FP64 is assumed.

Profile the reference first at each width, B16 training and B1 inference. Stage
profiling deliberately splits command buffers and is not a production timing.
Record GPU timestamps, host completion, dispatches and available resource
counters; unavailable occupancy/bandwidth/register counters remain unavailable.

The finite inventory is generated by `gpu_policy.candidate_inventory` and retained
under gpu-v2. Dense directions independently vary M16/32,N32/64,K16/32,SG2/4;
normalization varies SG1/2/4 and load width1/4; attention varies rows1/2, SG1/2,
Q register/threadgroup staging and saved/recomputed forward probabilities;
embedding index blocks64/128; fusion varies matrix epilogues and Adam/finite scan.
Reference is always eligible. QKV compensation is unchanged by the dense grid.
The trace-compatible attention implementation still writes its named diagnostic
intermediates; forward-probability recomputation initially retains the allocated
workspace, so no memory-capacity reduction is claimed for that candidate.

Freeze the executable candidate definitions and legality ledger before scoring.
Unsupported and failed candidates stay visible and are never ranked. Each
candidate first passes its development primitive/FP64 and complete-model checks.
Use 20 warmups and 100 observations in five blocks. Restore parameters/moments/
step after warmup and before each training block. Complete train-step samples
include finite checks and scalar loss completion. Inference is synchronized B1.
Visit families once in descending reference cost, name order for ties. Select a
replacement only for >=3% median complete-step improvement; select B1 separately.
No test data, admission data or unreported grid expansion enters selection.
Revalidate the final combined policy, including reference/optimized ablations.

Base order: cpu_arm64,cpu_torch,metal,mps,mlx; rotate by
(width_index+2*seed_index+repeat_index)%5 in each block. Freeze all180cells before
execution. One measured process; AC power; fixed one-thread host libraries;

Training includes forward/backward, reductions, Adam, finite checks, validation,
checkpoint writes, packing, synchronization and bookkeeping. Report setup,
compilation/warmup, final test and inference separately. Primary inference is B1

At each selected checkpoint, replay all validation/test sequences through all
five implementations and independent FP64 equations with the exact saved state.

repeat equality. Keep evidence integrity, repeatability, each engine's FP64
accuracy, mutual FP32 compatibility and predictive quality separate. Retain every
failed coordinate; post-training precision failures do not disappear behind NLL.

Report per-width paired ratios and raw samples, p50/p95, throughput, quality and
memory. Average repeats within seed for quality statistics, then report three-seed
mean/sample SD. No pooled-width headline speedup. Publish static scaling, accuracy,

and reproduction tools. Verify local/remote archive hashes, CI and device checks
before merge. A blocked engineering release is a valid outcome, with zero formal
