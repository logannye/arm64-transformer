# Prospective untouched-base control

This additive hosted build prepares a true pristine PyTorch runtime at `71d2a08507ab47dd6b2fa9b66319d17ce2377de4`. It investigates the 27 retained failures in the formatted-patch full MPS module. It is not a standard-release baseline, formal admission, a performance run, or a declaration that those failures pre-exist the patch. Do not launch until the serial isolated-test diagnostic establishes the need and the parent approves the hosted attempt.

The build copies the reviewed formatted-v2 helper's full-framework build, archive-before-validation, normal import, portability and archive-roundtrip procedures. It applies **no patch**. Git HEAD, index, working-tree changes and four relevant pristine file hashes are checked repeatedly. The editable `pip install -e . -v --no-build-isolation` command is the only framework build entry point. Maximum native parallelism remains two; one build tree and one environment are used on the hosted runner. No local framework compilation is requested.

`contract.json` binds the authenticated formatted run40989036595 receipt, exact45-wheel identities, complete dependency freeze, recursive submodule identities, declared build environment, selected CMake/compiler flags, host image/OS/Python version, Xcode/SDK/compiler identity and OpenMP bottle identity. Every wheel must match before installation, and the installed freeze must match before compilation. Compiler version, target and thread-model lines are exact; the compiler's `InstalledDir` mount location is retained but excluded from version comparison. The raw compiler and package logs remain evidence. Host/tool/version drift fails the comparison rather than silently describing unmatched builds as a pristine control.

The complete untouched `test/test_mps.py`, its source/Metal fixture closure, and upstream `LICENSE`/`NOTICE` are retained separately in `pytorch-pristine-test-source.tar.gz`, with raw hashes and canonical Git-blob identities. The nine unchanged test/helper function ASTs use explicit field serialization (including empty fields and tagged constants), avoiding Python-version-specific `ast.dump` formatting. Their structures, including decorators, are bound against the formatted source; they cover all 27 dynamic failed test IDs. This compact source transport supports a separate exact-ID or complete-module replay without copying another full upstream checkout locally. The framework's own test-support Python modules remain in its authenticated runtime. A later replay must authenticate the pristine runtime and source manifest independently; the patched runtime's gate cannot be reused as permission for different binary bytes.

Unmodified `spin lint` still runs and may retain base warnings. A failed lint job remains failed. Its runtime archive is retained before imports/lint, so diagnostic eligibility can be evaluated separately from complete hosted-job success. No exclusions or warnings-as-success conversion are introduced. All raw logs, receipts, native archive, source archive, dependency wheels and build metadata are uploaded, including on failure. The workflow uses the existing single PyTorch-build concurrency group.

The comparison is retrospective and diagnostic. Even a matching pristine failure cannot clear the original formatted full-suite failure or admit either development build into the 180-fit study.
